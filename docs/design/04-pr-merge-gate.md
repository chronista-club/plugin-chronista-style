## 判断と置き場

マージ条件の正本は [codeflow の「PR のマージ条件」](../../skills/codeflow/SKILL.md#pr-のマージ条件) とする。ユーザーによるマージの GO と、team-b のレビューによるマージ可判断を代替可能にし、レビューが通っていても追加の GO を待つ状態を解消する。

team-b の現行の quick レビューは `COMMIT READY / NEEDS WORK / BLOCKED` を返す。判定語を変更したり特定のラベルとマージ権限を直結させたりせず、メインセッションがレビュー対象・結論・残件と PR の必須チェックを確認する。team-b のロール定義とコミットラインは変更しない。

## 確認する場面

いずれも現在の差分に対する判断として読む。

| 状況 | 期待する進行 |
|---|---|
| マージへのユーザー GO があり、必須チェックを満たす | team-b レビューを追加条件にせずマージする |
| team-b のレビューがマージ可で、必須チェックを満たす | 判定の表記にかかわらず、追加 GO を求めずマージする |
| 実装開始の GO のみで、マージ可のレビューはない | マージ条件は未充足 |
| レビューに未解決の blocker や未充足の条件がある | レビュー経由の条件は未充足 |
| 必須チェックが失敗・未確認 | GO / レビュー結果だけでマージしない |
| 承認・レビュー後に差分が変わった | 更新差分への GO または再レビューで確認する |
| ユーザーが明示的にマージを保留している | レビューが通っていても保留解除を待つ |

スキルの構文・ローカル参照・配布は既存の検証で確認する。上の場面はレビューの観点であり、語句照合テストやモデルの行動評価を実施した証拠とはしない。

## やってはいけない

- レビューの判定名だけで、対象差分・残件・必須チェックの確認を省く。
- 実装開始の GO やマージ可判断を、リリース・デプロイまでの承認に読み替える。
