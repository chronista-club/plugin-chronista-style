# creo-memories の接続と未接続時の扱い

記憶の検索・保存・todo 更新を行うときに読む。Claude Code / Codex 共通。

## 接続済みのツールを使う

- 利用可能なツール一覧から creo-memories の目的の操作（`search` / `remember` / `list_todos` / `create_todo` / `complete_todo` など）を見つける。ツール検索機能がある環境では必要な操作だけを検索する。
- ツールの接頭辞やサーバー名の表記は環境で異なる。`mcp__creo-memories__remember` などの完全名を決め打ちせず、実際に提供された名前と引数スキーマを使う。同名の別サービスには書き込まない。
- Context Engine の記憶コンテキストが実際に届いていれば、その情報を使い、開始時に重複検索しない。このプラグインの git 情報・Atlas 候補だけでは、記憶が注入済みとは判断しない。
- 未注入で過去の経緯が必要なら、接続済みの `search` で対象を絞って補う。追加の API 作法は、利用可能なら creo-memories スキルに従う。

## Atlas 候補

SessionStart が出した候補を使う。hook が動いていなければ、作業ディレクトリの basename と、git remote のリポジトリ名から候補を得る。`claude-plugin-` / `codex-plugin-` / `plugin-` / `skillset`（直後の `-` は任意）の接頭辞を除いた名前も候補にする。

候補名は Atlas ID ではない。既に取得した Atlas 情報と exact match する場合だけ、その ID を指定する。対応が不明なら同じ repo の過去の todo の Atlas に倣い、前例も無ければ `atlasId` を省略して Personal に保存し、一言添える。ID を推測で生成しない。置き場の確認だけで作業を止めない。

## 未接続・失敗時

- ツールが無い、認証が必要、通信に失敗した場合、記憶操作は未実施と短く報告する。検索できなかったことを「過去の記憶なし」と読み替えない。
- 記憶を必須としないコード・調査・文書作業は、現在の会話とリポジトリの情報で続ける。過去の裁定が必須の判断だけは不足を明示する。
- 保存専用の `spark` は、ユーザーの原文をそのまま会話に返し「未保存」と明記して終える。memory ID を作らない。
- todo の作成・完了、PR の memory ID 記載も実際の操作結果がある場合だけ行う。未接続時は memory ID を省略し、未同期の内容を報告する。
- 保存がタイムアウトして成否不明なら「保存結果未確認」とする。重複保存を避けるため、確認せずに再送しない。

このプラグインは接続や認証を自動で作成しない。MCP 接続の設定・配布は別途行う。
